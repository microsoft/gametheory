# Flood response lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Exercise participants acknowledge synthetic shelter requests and allocate resources.
Observers inspect run evidence. A separately authorized operator prepares runs and
conditionally recovers unchanged synthetic records.

## Product Purpose

A small independent operational system, not a Game Theory portal or installer.
Successful use leaves durable, attributable request and allocation evidence.

## Capabilities and Constraints

The approved brief requires real Entra sign-in, server-side actor/run grants, a
dedicated SQL Server database, conditional writes and idempotent reconciliation.
No participant seed, reset or approval controls. No Graph sender implementation.
All people and places are fictional. Missing configuration is a setup-required
state, never a demonstration login.

## Brand Commitments

The brief pins a sober operational interface, not a branding project. Inherit the
incumbent mineral/ocean character without sharing its code or runtime.

## Operating Context

Assumption from the brief: coordinators work at ordinary desktops and phones in
lit exercise rooms. Start with a light task-oriented layout and honor system dark
mode. No external fonts, images or analytics are needed.

## Accessibility & Inclusion

Typed, keyboard-operable forms; explicit labels and focus; responsive request
lists; durable status text rather than color-only indicators.
